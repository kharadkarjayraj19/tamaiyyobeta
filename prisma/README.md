# Tamayo — Prisma directory

**Purpose:** Prisma schema, migrations, configuration, and seed scripts for Tamayo marketplace database.

**Architecture:** See `docs/architecture/prisma-data-architecture.md` and `docs/architecture/prisma-schema-planning.md`.

---

## Directory structure

```
prisma/
├── schema.prisma           # Prisma schema (21 models, 13 enums)
├── seed.ts                 # Database seed script
├── migrations/             # SQL migrations (version controlled)
│   ├── migration_lock.toml # Provider lock (PostgreSQL)
│   └── 20260518_init/      # Initial migration
│       └── migration.sql   # SQL for all tables, indexes, FKs
└── README.md               # This file
```

**Note:** DATABASE_URL is configured via `src/lib/db/prisma.ts` (PostgreSQL adapter pattern for Prisma 7.x).

## Files

### `schema.prisma`

Prisma schema defining 21 models across 5 modules:

| Module | Models |
| --- | --- |
| **Identity** | `Identity`, `CustomerAccount`, `SupplierAccount`, `AdminAccount` |
| **Vehicle** | `Vehicle`, `Driver` |
| **Booking** | `Booking`, `BookingItinerary`, `BookingPricingSnapshot`, `AssignmentHistory`, `TripExecution` |
| **Billing** | `Quote`, `FinalBill`, `CommissionSnapshot`, `Payment`, `Refund`, `SupplierEarning`, `PayoutBatch` |
| **Cross-cutting** | `Upload`, `DomainEvent`, `SupportNote` |

**Enums:** 13 lifecycle/state enums (e.g. `BookingStatus`, `PaymentStatus`, `VehicleStatus`)

**Key patterns:**

- UUID primary keys (`@default(uuid())`)
- `Decimal(10,2)` for monetary fields
- `createdAt` / `updatedAt` on mutable entities
- `deletedAt` soft-delete on operational entities only (Vehicle, Driver, Upload)
- Immutable snapshots (Quote, FinalBill, CommissionSnapshot) with `createdAt` only
- Append-only history (AssignmentHistory, DomainEvent, Refund)

### `seed.ts`

TypeScript seed script for initializing database with foundational data.

**Current status:** Placeholder structure only; no operational data.

**Planned seeds:**

- Admin accounts (when auth wiring complete)
- Pricing configuration versions (when pricing module added)
- City/corridor data (when city config added)

Run: `npm run db:seed` (or `npx prisma db seed`)

### `migrations/`

Version-controlled SQL migrations generated by Prisma Migrate.

**Initial migration:** `20260518_init/migration.sql` — creates all tables, indexes, enums, foreign keys from scratch.

**Future migrations:** Generated via `npm run db:migrate:dev --name description`.

**Production:** Applied via `npm run db:migrate:deploy` (no new migration creation).

## Schema evolution workflow

1. **Modify `schema.prisma`** (add/change models, fields, enums)
2. **Generate migration:** `npm run db:migrate:dev --name my_change`
3. **Review migration SQL** in `prisma/migrations/[timestamp]_my_change/migration.sql`
4. **Test migration** in development database
5. **Commit migration** to git
6. **Deploy to production** via CI/CD with `db:migrate:deploy`

## Migration best practices

1. **Always review generated SQL** before committing migrations
2. **Test migrations in staging** before production
3. **Use transactions** for multi-statement migrations
4. **Avoid breaking changes** without data migration strategy (add nullable fields, backfill, make required)
5. **Backup production** before applying migrations
6. **Monitor migration performance** on large tables
